# Business tools — October 5, 2026

The new tools extend the approved CRM without editing the month calendar or Visualizer.

- Receipts: choose a JPEG/PNG/WebP image, scan, review extracted fields, apply, then save through the existing receipt editor. Missing dates/amounts stay empty. Currency other than explicit USD requires confirmation. Scanning never inserts an expense.
- Magic wand: record up to 90 seconds or upload up to 8 MB of audio, review the transcript and append it to editable notes. Draft generation and financial-document saving remain separate actions. Microphone tracks stop on navigation or dismissal. Technicians must select their assigned job.
- Office / Reports: owners can review projected job margins over a selected date range, record actual processing cost and confirm parts costs. Pre-tax discounted invoice revenue follows existing payroll calculations. Commission uses the assigned technician's roster rate, including the existing negative-profit behavior. Parts reimbursement is not subtracted again. These are projected job margins before overhead, not business net income. Changes to revenue, material cost, commission rate or fees invalidate the prior review. Default low-margin alert threshold is 20%; owners can change it. Dashboard alerts cover invoiced jobs scheduled in the last 30 days.
- Office / customer file / Tasks: maintenance plans are versioned recurring task records in existing `tasks.app_data`, secured by existing role policies. Agreements last up to one year and support annual, semiannual, quarterly or monthly visits. Reminder tasks become due before the service date; dashboard shows internal reminders. No automatic customer messaging or billing. Completing a confirmed visit appends history and advances the same task; the last visit expires the plan. Compare-and-swap on `row_version` prevents competing completions from overwriting history. Editing a maintenance task opens the maintenance editor.
- Office / Jobs / technician dashboard: build a daily route from the selected technician's remaining visits. Appointment windows retain their order. A nearest-neighbor straight-line heuristic reorders stops only inside identical windows with all coordinates available; this is not a global optimal route or live traffic calculation. US Census locates the saved job service address server-side, falling back to the customer address when no job override exists. Unmatched addresses and unconfirmed time windows are shown for review. Maps links split into four-stop segments so mobile browser waypoint limits never drop stops. Optional geolocation supplies the starting point. Building a route does not reschedule jobs.

`business-assistant` validates the bearer token with Auth, checks an active roster membership and role, verifies technician job ownership, limits request/file sizes, caps requests per member/hour and records audit events without receipt/audio content. The provider key stays server-side. A service-role client is used only after authorization. Financial records are not created by the function. Transcription uses `gpt-4o-mini-transcribe`; receipt extraction uses `gpt-4.1-mini` with non-persistent Responses and validated JSON output. The function's gateway JWT check is disabled because its body explicitly validates every request via `getUser()`.

Release tests cover receipt uncertainty, date/cost validation, margin calculations, short-month recurrence, appointment-window boundaries, mobile Maps segmentation, active-member/job authorization, multipart transcription, provider failure, stored-address lookup, rate limits and competing updates. Browser checks use synthetic records with mocked provider responses; no real customer documents or payments are created.

Browser verification: `node scripts/verify-business-tools-browser.cjs` with Playwright available under `CODEX_PRIMARY_RUNTIME_NODE_MODULES` and `CHROMIUM_EXECUTABLE` set to an installed Chromium binary. Screenshot output defaults to `/tmp/ezfix-business-tools` or `BUSINESS_TOOLS_SCREENSHOTS`. The fixture extracts the real modal/receipt editor and styles from index.html and loads the actual tool scripts. It exercises all five workflows against synthetic records and mocked AI/geocoding responses.
