# Banking, receipt archive, and social drafts

The Banking page reads the existing production Square connection. The new owner-only `business-finance-status` function uses GET requests to the Bank Accounts and Payouts APIs and returns bank name, account suffix, status, and the latest 20 payouts. It never exposes bank routing numbers, account holder details, API credentials, or a fabricated available balance. Bank linking is completed in Square. The live verification found one verified Bank of America account and 13 payouts.

Payroll calculations remain in the existing payroll module. No CRM wallet, outbound bank transfer, Zelle instruction, or payment confirmation was introduced. Bank of America disbursements require separate business-payment enrollment/provider integration, verified recipients, and an actual provider result before a payout can be recorded as sent. A payroll CSV can already be exported for review.

The existing receipt database trigger and one-minute cron remain unchanged. Live verification found three ready receipt jobs, three stored PDF assets, no pending/failed jobs, and ten successful cron executions in the latest ten-minute window. Closing a lead alone does not qualify as payment. The customer receipt view filters fully paid, nondeleted invoices by final payment year; it provides customer/invoice search, a formula-safe CSV and a ZIP with server-generated PDFs plus the CSV. Supplier receipts remain separate. ZIP errors abort the download instead of silently omitting a PDF.

`generate-social-post` checks active office membership, enforces topic/notes limits and an hourly generation allowance, and uses the existing server AI credential. The text prompt requests substantial platform-sized posts without invented job history or unsafe DIY spring instructions. An optional illustrative image is generated and stored privately in `crm-assets/social/generated/`. Existing signed asset URL hydration renews links after loading saved posts. Generated drafts and images can be reviewed, saved, copied and downloaded; no social API publishing is performed, because the current account-publishing integration remains pending. Image failure preserves the generated text draft and reports the failure.

Both Edge Functions are deployed with gateway JWT verification disabled because they validate the user through `auth.getUser` and active team membership themselves. A secret-protected, read-only `validate_only` diagnostic is available only in `business-finance-status`; it returns counts, bank names, and AI model-access booleans, never credentials or complete bank records. Deploy the functions with this setting and their checked-in dependencies. No new credentials were created.

Verification: full release gates, annual receipt/filter/CSV/ZIP tests, independent Python ZIP parsing, owner/office/technician authorization tests, masked read-only bank API tests, generated-image persistence and provider-failure tests, and DOM checks for draft fields, selected platform/photos, and preservation of user edits. Live checks confirm receipt storage/cron, Square bank/payout access, and AI text/image model access. AI generation itself is tested with controlled provider responses; no marketing post was published and no money moved. Browser visual verification was unavailable in this environment.
